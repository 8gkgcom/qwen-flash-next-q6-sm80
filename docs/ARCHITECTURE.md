# 实现、贡献与边界

## 数据路径

```text
OpenAI 请求 → 2 运行 / 4 等待的 FIFO → vLLM PP2 调度
                                         │
                    token + n-gram 历史 → PLE CPU worker
                                         │
                       内存 mmap + mlock 的 Q8_0 大表
                                         │ 只解码命中行
                                    BF16 输出缓冲
                                         │ CPU → GPU
                 GPU0：25 个主模型层 → GPU1：23 层 + MTP
```

这里放在系统内存的是 PLE 模型查表权重，不是把 KV cache 扩展到主机内存。mmap 的文件页通过 mlock 常驻，源 GGUF 不修改。所需内存包括约 50.66 GiB 压缩表、运行时、加载临时区和页缓存；96 GB 是参考机器配置。

## 精度与验证范围

- PLE 行解码的 F32 / BF16 数值与参考反量化进行比较，包括全部 FP16 缩放编码、边界索引、空输入和原缓冲输出。其精确性只适用于这个行解码环节。
- 主权重保持原 GGUF 量化格式。GGUF GPU 内核包含 A8 激活路径，不能描述为与整模型 FP32 / BF16 完全相同。
- 草稿词表筛选增加约 644 MiB 显存，原 Q8 权重保留。先筛选 top-32 不是全词表精确 argmax 的数学保证；候选最终仍走目标模型的推测解码验证。有限输出哈希一致不等于对任意输入的输出相同证明。
- 异步 H2D 只改变元数据传输方式，不改模型运算公式，但仍需在指定版本上验证异步缓冲生命周期与调度顺序。
- `q6_shortconv_async` 使用源码变换和数量断言；动态图、IPC 和草稿优化使用版本相关钩子。上游升级必须重新审阅、编译和回归，不可视为通用插件 ABI。

## 与 SM80 上游的差异

参考上游的主路径是 NVFP4 / GDS 等优化组合。本项目固定其 v0.2.0 基础，选择 GGUF Q6_K、系统内存 Q8_0 PLE、PP2 和动态 MTP2/1，并保留使异步多请求可用的兼容修改。没有同步上游后续主版本，也不把上游的吞吐数字当作本模型的对照成绩。

历史测试实际观察到 NCCL SHM 传输；即使配置允许 P2P，也不能宣称本项目测得了 P2P 提速。GPU busy 指标还可能包含通信等待。

## 公开项目与原部署的差异

核心数值代码按运行版本提取；发布整理只参数化本地目录、移动模块命名空间、将行解码动态库改为包内相对位置，并补上独立构建、API 排队和验证脚本。原控制台的管理页面、鉴权数据库、挖矿、电源操作和其它模型适配没有带入。公开包提供 OpenAI 风格 API，不包含原控制台的 Anthropic 协议转换。

覆盖层中保留了一些上游辅助代码，运行时明确关闭 NVFP4 RAM compute hooks、GDS 和混合历史草稿开关。这些保留源文件不意味着其可选路径经过本 Q6 组合验证。
