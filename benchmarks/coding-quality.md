# 代码质量验收题

这些题与测速题的主题一致，但需要完整回答。它们是人工审阅的验收规格，不是已完成的代码能力评分，也不把任意生成代码自动执行到服务器上。

固定采样和工具权限；每道题允许至少 8192 输出 tokens，必要时继续到完整答案。记录到达输出上限的次数，不把截断直接计为算法失败。代码在隔离测试环境运行，使用确定性时钟、同步屏障和明确的超时。

## TTL / LRU 缓存

使用 `benchmarks/prompts.json` 的 `ttl-lru` 题。要求明确 API、容量、TTL 起算点和并发语义。

验收点：容量 0 和 1、更新同一个键后的旧过期事件、相同过期时间的不可比较键、过期与 LRU 淘汰交错、注入时钟前进、两个线程同时更新/读取、清理不扫描全表、过期索引长时间更新后的空间上界。解释加锁边界，不能依赖真实 sleep 让竞态“恰好不发生”。

## 可取消重试任务队列

使用 `task-queue` 题，要求实现一个可测试的核心状态机。先定义取消已执行副作用时的承诺，区分任务去重和外部副作用幂等。

验收点：重复提交、同一任务并发领取、超时后旧 worker 晚到、取消与完成竞争、重试计数和退避、进程崩溃后的租约回收、终态不可逆、不会无故饿死新任务。用条件更新或 fencing token 防止过期 worker 覆盖新状态。需要列出哪些属性取决于外部存储/事务。

## 数学证明

使用 `integer-proof` 题。正整数或正实数约束下，最大值均为 `512000000`，在 `a=b=c=20` 取得。验收要求包含可检查的全局上界与取等条件，不能只枚举整数或只说明对称点是驻点。可用 AM-GM 分别给出 `abc <= 20^3`、`(a+b)(b+c)(c+a) <= 40^3`。

## 温度对照记录

若比较 0.6、0.8、1.0，每个温度用同样的多组种子、相同输出预算、相同测试与超时。逐题记录完整答案率、测试通过率、生成 token 数、端到端时间及失败类型。现有仓库数据没有完成该比较，因此没有“最佳编码温度”的实证结论。
